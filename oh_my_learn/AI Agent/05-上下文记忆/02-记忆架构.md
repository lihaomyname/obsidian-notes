# 记忆架构

> 记忆系统负责跨步骤、跨会话保存可再次利用的信息，并通过明确的写入、检索、更新和遗忘策略把相关内容送回上下文。

## 记忆类型

AI Agent Book 链接给出四类划分：

| 类型 | 作用 | 常见位置 |
| --- | --- | --- |
| 工作记忆 | 当前正在处理的局部信息 | 上下文窗口、执行状态 |
| 会话记忆 | 当前线程的对话和任务状态 | Checkpoint、缓存或数据库 |
| 长期记忆 | 跨会话保留的偏好、事实和经验 | 关系数据库、文档或 Store |
| 语义记忆 | 按语义召回相关历史和知识 | 向量索引与文档存储 |

这是一种工程划分，不是唯一分类法。课程资料更概括地强调短期记忆与长期记忆分离。

## 记忆生命周期

### 写入

不应把每条对话都永久保存为高价值记忆。写入前需要判断来源、可信度、作用域、敏感性和未来复用价值。

```python
from dataclasses import dataclass
from datetime import datetime

@dataclass
class MemoryRecord:
    id: str
    namespace: str            # user / project / organization
    kind: str                 # preference / fact / episode / procedure
    content: str
    source: str               # 用户原话、文件路径或工具调用 ID
    confidence: float
    created_at: datetime
    valid_from: datetime
    valid_until: datetime | None
    sensitivity: str
    embedding: list[float] | None = None
```

来源和有效期是重要字段：模型推测不能伪装成用户确认的事实，旧偏好也不能永久压过新偏好。

### 写入门控

```python
def should_remember(item):
    if item.is_secret or item.has_no_future_value:
        return False
    if item.is_model_inference and not item.was_verified:
        return False
    return item.user_explicitly_requested or item.expected_reuse_count > 1
```

示例规则表达的是门控思想，实际系统还要处理合规、租户策略和用户删除请求。

### 检索

课程资料提出关键词、向量和图结构的混合检索。不同信号各有用途：

- 关键词适合精确名称、编号和术语。
- 向量适合语义相近但措辞不同的内容。
- 图关系适合实体和关系约束。

混合检索可先分别取候选，再做融合和重排：

```python
def retrieve(query, scope, k=8):
    lexical = keyword_search(query, scope, top_n=30)
    semantic = vector_search(query, scope, top_n=30)
    relational = graph_expand(extract_entities(query), scope)

    candidates = fuse(lexical, semantic, relational)
    candidates = filter_by_permission_and_validity(candidates, scope)
    return rerank(query, candidates)[:k]
```

权限和有效期过滤必须在注入模型前完成。融合可以使用排名融合或归一化分数，但不同检索器的原始分数通常不能直接相加。

### 更新与冲突

用户偏好或事实会变化。新旧记忆冲突时应保留时间、来源和版本，而不是简单覆盖后假装始终一致。

### 遗忘与衰减

删除或降权低价值、过时和重复记忆，以免召回污染。课程资料提到 Memory Decay，但没有规定唯一算法。

一个可解释的排序分数可以综合：

```text
最终分数 = 语义相关性 × 新鲜度 × 可信度 × 作用域匹配
           + 关键词命中加分 + 明确用户固定记忆加分
```

衰减不等于直接删除。可先降低召回权重，再归档，最后按保留策略删除；用户明确要求永久保留或删除的内容应走独立规则。

## 冲突处理例子

```text
旧记录：用户偏好 Python 3.11（来源：项目 A，2025-01）
新记录：项目 B 固定 Python 3.12（来源：pyproject.toml，2026-03）
```

这两条不一定矛盾：作用域不同。检索时应优先匹配当前项目；若同一作用域真正冲突，则保留两条及时间，标记旧记录失效，而不是无痕覆盖。

## 一次完整的记忆回路

```text
对话/工具结果
  → 提取候选记忆
  → 写入门控与去重
  → 保存内容、来源、作用域和索引
  → 新任务到来
  → 混合检索与权限过滤
  → 重排少量高价值条目
  → 注入当前上下文
  → 使用反馈更新权重或纠错
```

## 存储职责

链接资料展示的 Shannon 示例分别使用 PostgreSQL、Redis、Qdrant 承担事务数据、热状态和向量检索。该组合是一个实现案例，不是通用强制方案。

另一种方式是本地文件：透明、可编辑、适合版本控制，但跨设备同步、规模和语义检索能力较弱。

## 记忆与上下文的区别

```text
记忆：存在哪里、写什么、如何检索和遗忘
上下文：当前这一次模型调用实际看到什么
```

记忆只有被正确召回并注入上下文，才会影响当前决策。保存成功不等于以后一定能想起来。

## 隐私与权限

- 明确用户、会话、项目和组织作用域。
- 敏感数据不进入无权限共享记忆。
- 给用户查看、修改和删除长期记忆的能力。
- 记忆条目保留来源，避免把模型推测长期保存为事实。
