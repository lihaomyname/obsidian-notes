# 上下文工程

> 上下文工程管理模型在当前调用中能看到的指令、历史、记忆、检索结果、工具和输出要求，目标是在正确时间提供足够而不过量的信息。

## 上下文窗口的性质

Wayland 的链接把上下文窗口类比为 RAM：

- **有限**：内容最终会达到窗口和预算上限。
- **易失**：单次会话结束后不会天然跨会话保留。
- **昂贵**：输入越长，延迟和费用通常越高。

更大的窗口不代表可以无差别塞入更多内容。无关历史和冗长工具结果会稀释关键信息。

## 上下文包含什么

- 系统指令与行为边界
- 用户当前目标
- 对话和执行历史
- 长期记忆召回结果
- RAG 或文件检索结果
- 可用工具的 Schema
- 输出格式和验收要求

上下文工程比单纯修改 Prompt 更宽：Prompt Engineering 主要关注“怎么说”，上下文工程关注整个系统“让模型看到什么”。

## 四类策略

### Write：写到窗口之外

把计划、关键发现、待办和大段原始结果写入文件或外部存储，需要时再读回。Scratchpad、任务清单和项目说明文件都属于这一类。

### Select：按需选择

核心信息预加载，详细文件、历史记录和知识通过搜索或 RAG 在需要时取回。渐进式披露的原则是先提供索引和线索，再读取具体内容。

### Compress：压缩历史

用摘要替换冗长中间历史，同时保留初始目标、关键决策、未解决问题和最近对话。压缩是有损的，应保留 URL、文件路径等可恢复线索。

### Isolate：隔离子任务

把会产生大量中间信息的子任务交给独立上下文，只返回精炼结果。子 Agent 是一种隔离方式，但不是唯一方式。

## 与 RAG 的关系

RAG 主要解决“检索哪些外部知识”；上下文工程还管理指令、历史、工具、状态、预算、压缩和隔离。RAG 是 Select 策略中的一部分，不等于完整上下文工程。

## 课表中的 VFS

课表特别提到虚拟文件系统。结合链接资料，可把它理解为一个受控的上下文外存储层：Agent 通过文件接口写入、搜索和读取资料，以路径组织内容，并由 Backend 或沙箱决定这些路径映射到本地文件、状态存储还是远程 Store。
