# 对话知识整理

把当前对话中值得复习的技术知识沉淀到当前项目的 `oh_my_learn/`。产物应是可独立阅读、便于以后检索的入门教程，而不是聊天记录的逐句转写。

## 确定保存位置和语言

1. 找到当前对话实际对应的项目根目录。优先使用与当前任务相关的 Git 根目录；没有 Git 时，根据项目清单、源码目录和当前工作目录判断。不要把 skill 自身的安装目录、用户主目录或无关的上层仓库误当成目标项目。
2. 检查项目文件、构建清单和本次对话涉及的代码，判断主要编程语言。通用概念也使用该语言给出示例。多语言项目只整理与本次对话相关的语言；若无法安全判断目标项目或语言，先询问用户。
3. 说明文字默认使用用户对话所用的自然语言，代码保持项目所用的编程语言。

## 选择知识点

- 以当前对话为范围，提取用户刚刚询问、容易遗忘或后来被纠正的概念、语法、工具用法和调试经验。
- 采用对话最终确认的结论，忽略已经被推翻的中间答案。
- 可以补充理解这些知识所必需的基础背景，但不要扩展成与对话无关的语言教程。
- 不记录密码、令牌、个人信息、内部地址等敏感内容。示例中出现这些值时改用明显的占位符。
- 不虚构项目行为、命令输出或尚未验证的结论。不确定的内容明确标注，必要时先查证。

## 组织文件

在项目根目录创建并维护以下结构：

```text
oh_my_learn/
├── README.md
└── <language>/
    └── <topic>.md
```

- `README.md` 是简短索引，列出语言、主题及对应的相对链接。
- 每个文件聚焦一个清晰主题；相关知识优先合并，互不相关的知识分文件保存。
- 目录名和文件名使用稳定、易读的名称。语言目录使用社区常见的小写名称，例如 `python`、`java`、`typescript`。
- 写入前先检查 `oh_my_learn/` 的现有内容。相同主题应增量更新原文件、消除重复并修正旧错误；保留用户手写内容和现有组织方式。不要仅因再次触发就生成重复笔记。
- 所有索引链接使用相对路径，并在增删主题后同步更新。

## 初学者笔记标准

根据主题需要组织内容，不必机械套用固定标题，但一篇完整笔记通常应包含：

- 这个知识解决什么问题，以及它在本次对话中的使用场景；
- 一句话定义，再用直观类比或心智模型展开解释；
- 关键语法或规则，逐行解释首次出现的术语；
- 至少一个最小、可运行或可验证的项目语言示例，并解释输入、执行过程和结果；
- 常见错误、容易混淆的概念及排查方式；
- 与项目现有代码相关时，指出真实文件或模块，但只引用已检查过的内容；
- 一段简短总结，以及适合初学者自行尝试的小练习或检查问题。

细节应足以让刚入门的读者脱离当前聊天也能看懂。避免只给定义、堆砌术语或复制大段项目代码。示例应尽量小，并与项目实际版本和编码风格一致。

## 完成后

检查 Markdown、相对链接和代码示例的一致性。向用户说明识别出的项目语言、创建或更新了哪些笔记文件，以及哪些内容因不确定而未写入。
